# Routing v5: clarify the desired outcome

Two frozen, single-attempt routing batches reached every expected outcome on
the existing synthetic suite: 57/57 in each batch, with no malformed
probability distributions or retries. The subsequent full CLI comparison reached
56/57 expected routing outcomes, retaining one malformed response as unavailable.
These are repeated development cases, not held-out calibration. Routing-only
results do not measure delivered-answer quality.

## Change and frozen setup

Candidate source:
[`fda2774667872968e1ef48271faa040e435ffdfc`](https://github.com/TypeSafeAI/jev-harness/commit/fda2774667872968e1ef48271faa040e435ffdfc).
The frozen source is signed and passed 268 offline tests, typecheck, production
build, secret checks and independent compatibility review before measurement.
After measurement, delivery added one offline replay test for the retained H
artifact: the final delivery passed 269 tests, typecheck, production build and
secret checks. These are distinct verification runs; the runtime source remains
identical to the frozen candidate.
[CI for the 269-test delivery](https://github.com/TypeSafeAI/jev-harness/actions/runs/36228552912)
also passes.

V5 changes only the generic clarification wording from v4: a named target is
not a specified outcome; materially different possible outcomes require
clarification; a vague improvement request does not establish a concrete edit.
The model, catalog, tasks, labels, mocks, policy, confidence floor, probability
validation, prerequisites and fixture host remain fixed. V1–v4 request bodies
remain available unchanged for replay. Arena setup 6 separates new runs from
older cohorts.

This follows the [v4 wire diagnostic and bounded recovery experiment](2026-09-26-distribution-diagnostic.md).
The single-attempt control reached 53/57. Maximum-three-attempt recovery reached
57/57 then 56/57, with additional provider usage and one exhausted case. Recovery
was not integrated. V5 asks a clearer question while retaining the same strict
evidence contract; it does not repair, normalize or tolerate malformed output.

recorded constraint violation enter this comparison. All outcomes remain in

Input/output include Jev when called; cached input is proposer-only because no

## Limits

The existing cases influenced development, so this is adaptive tuning. Repeated
runs test variability on these cases, not independent task coverage. Zero
malformed responses in the routing-only batches did not prevent a malformed
response in the full batch. Correct clarification is an expected routing
outcome, not a delivered answer or authorization.

Proposal-review wording and verdicts remain unchanged; its
[200/200 observed result](../calibration/2026-09-25-question-set-v4.md) is separate
evidence and not a routing score. Future recovery or clarification delivery work
requires its own measured change; this wording change adds neither.
