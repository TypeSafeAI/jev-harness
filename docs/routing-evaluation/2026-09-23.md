# Live routing experiment, 2026-09-23

Refs [issue #2](https://github.com/TypeSafeAI/jev-harness/issues/2).

**Result: top-1 routing reduced reported input, but did not preserve tool use on
multi-step tasks. Keep those tasks in shadow mode while testing capability
bundles.** Correct clarification improved the aggregate score; it does not
cancel the regression among tasks where the router selected a tool.

All results below come from the [three-repetition artifact](../../examples/routing/runs/2026-09-23-routing-r3.json)
and its [regenerated table](../../examples/routing/runs/2026-09-23-routing-r3.md).
These are repeated synthetic tasks, not independent held-out examples.

You can regenerate the table offline without credentials:

```sh
pnpm --silent experiment:routing --table examples/routing/runs/2026-09-23-routing-r3.json
```

## What happened

| All 57 paired trials per arm | All available tools | Jev top-1 |
| --- | ---: | ---: |
| Correct tool or expected clarification | 27/57 (47%) | 33/57 (58%) |
| Reported input tokens, total | 1,982,251 | 771,760 |
| Reported input tokens, mean | 34,776 | 13,540 |
| Reported output tokens, total | 11,601 | 11,638 |
| Proposer invocations | 57 | 30 |
| Routed clarification | 0 | 24 |
| Unavailable routing evidence | 0 | 3 |
| Proposer completed without a tool call | 0 | 15 |

Reported input fell by 61%, including Jev overhead. This is not a 61% cost or
task-completion improvement: 27 routed trials never started the proposer, and
15 of the remaining 30 made no tool call. All trials reported input and output;
unknown usage was not converted to zero. Proposer-reported cached input was
1,546,112 tokens for the baseline and 528,896 for Jev top-1, so raw input totals
also cannot establish dollar savings. The 57 Jev calls had median host-observed
latency of 243 ms; this is not end-to-end execution speed.

The useful decomposition is:

| Same task/repetition pairs | All available tools | Jev top-1 | Interpretation |
| --- | ---: | ---: | --- |
| 30 pairs where Jev selected a tool | 27/30 correct | 15/30 correct | Selected schemas did not preserve multi-step capability. |
| 18 expected-clarification pairs | 0/18 correct | 18/18 correct | Withholding tools matched the frozen labels. Answer quality was not graded. |
| 9 inspect pairs | 0/9 correct | 0/9 correct | Jev clarified six and returned unusable evidence three times. |

For the selected subset, mean reported input was 38,062 with all tools and
25,114 with Jev. This subset is diagnostic, selected after observing routing;
it is not a replacement benchmark denominator. Patch tasks explain nine
misses: the baseline called an acceptable tool in 9/9, while Jev top-1 called
none in 9/9. The routed proposer lacked the read tool needed before proposing
the patch. Test-drafting tasks add six routed no-call outcomes. Read tasks
were correct in both arms (9/9); search selected the labelled tool in both
(6/6), but those search descriptors have no implementation.

Three trials retained unavailable evidence: repetition 2 `inspect-large`,
and repetition 3 `inspect-medium` and `inspect-large`. Their receipt reason
groups missing, malformed, out-of-set and model-mismatched evidence. The raw
invalid response is not retained, so this run cannot identify the specific
condition or establish a provider outage. These trials remain incorrect in
the denominator; they were neither retried nor discarded.

## What catalog growth shows

The overall size buckets mix different tasks. A narrower comparison keeps
the **read intent** constant, with three repetitions per size and 3/3 correct
in both arms:

| Available schemas | All tools: mean input | Jev top-1: mean input, including router |
| ---: | ---: | ---: |
| 3 | 29,831 | 29,842 |
| 8 | 30,720 | 29,966 |
| 20 | 32,814 | 30,291 |

For this intent, the routing request slightly outweighed schema reduction at
three tools; the input gap grew at larger catalogs. This is a limited signal
for the catalog-growth hypothesis, not evidence that top-1 works for every
task. Each of the three repetitions had the same aggregate correct counts
(9/19 baseline and 11/19 routed), while unavailable routing varied from zero
to two cases.

## Next experiments

1. Keep full schemas active in shadow mode for tasks that need read-then-patch
   or read-then-test. Test host-approved capability bundles or dependency-aware
   exposure before adopting lean mode. A larger `topK` alone does not guarantee
   prerequisites survive probability and relevance floors.
2. Report correct clarifications, incorrect clarifications, unavailable evidence
   and selected-but-unused tools separately. Review final answers and proposed
   patches before treating correct-tool rate as task quality.
3. Add redacted structural diagnostics for invalid routing evidence on the
   host, then repeat the inspect cases without relaxing evidence validation.
4. Capture and pin the actual proposer model on the next run. Compare cached
   and uncached usage, repeated end-to-end latency, and answer quality before
   drawing cost or performance conclusions.

No routing policy, question, model pin, threshold, verdict or execution behavior
changes in this report. The result does not justify lowering a confidence floor.

## Evidence and reproduction

The experiment uses the synthetic tasks, labels and policy at
[`c2493b2`](https://github.com/TypeSafeAI/jev-harness/commit/c2493b269be17de5924a4fea12ba1a52461bbf27).
The task labels were fixed before either run. The pilot was a transport and
artifact check; it is kept separate from the repeated experiment.

- [Pilot artifact](../../examples/routing/runs/2026-09-23-routing-pilot.json)
  and [regenerated table](../../examples/routing/runs/2026-09-23-routing-pilot.md).
- [Repeated-run artifact](../../examples/routing/runs/2026-09-23-routing-r3.json)
  and [regenerated table](../../examples/routing/runs/2026-09-23-routing-r3.md).

The host was macOS with `codex-cli 0.155.1`. Jev was pinned to `jev-1.13.0`.
The proposer used the isolated CLI's default model; its actual model identifier
was not captured. This limits reproduction across CLI defaults and future
provider changes. No real repository content, proposed-code execution, or
fixture evaluation labels reached either provider.

```sh
# Credential supplied by the host secret store; never placed in the artifact.
pnpm --silent experiment:routing --live --runs 1 --sizes small \
  --out examples/routing/runs/2026-09-23-routing-pilot.json
pnpm --silent experiment:routing --live --runs 3 \
  --out examples/routing/runs/2026-09-23-routing-r3.json
pnpm --silent experiment:routing \
  --table examples/routing/runs/2026-09-23-routing-r3.json
```

```sh
pnpm exec tsx -e '

  const selected = new Set(run.trials.filter(t => t.routing?.outcome === "selected").map(t => `${t.run}/${t.taskId}`));
  console.log(JSON.stringify(summarizeExperiment(run.trials.filter(t => selected.has(`${t.run}/${t.taskId}`)), run.labels).byArm, null, 2));
})();'
```

## Interpretation limits

Correct-tool rate measures an observed acceptable call or a labelled
clarification. It does not grade the final answer, patch correctness, or task
completion. Extra catalog descriptors record calls and return an error; they
have no executable handlers.

The generated table's `First call correct` field also counts expected
clarifications with no call. For the routed arm, its 33 consists of 15 actual
acceptable first calls and 18 expected clarifications; it is not 33 tool calls.

The small catalog has the five shared intents. Medium and large also include
search and test-drafting intents, so their overall means are not a controlled
catalog-size comparison. Compare the shared intents separately when judging
how schema count changes usage.

Reported input includes Jev routing overhead. A routed clarification does not
start the proposer, so its smaller input reflects abstention as well as schema
selection. Report selected and clarified routes alongside aggregate usage.
Input/output token totals are provider reports; byte proxies are separate.
Cached input, CLI startup, repeated reads and answer length can change totals.
These runs do not establish dollar savings, execution speed or production
error rates, and they do not calibrate a threshold.
